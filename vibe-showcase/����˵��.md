# Vibe Coding 展示页 · 交接说明

（写给负责把它集成进作品集网站的助手/对话）

## 包里有什么

| 路径 | 内容 | 能不能改 |
|---|---|---|
| `index.html` | 展示壳：左侧 390×844 手机视口（鼠标→触摸模拟、长按、缩放、引导演示引擎）+ 右侧项目信息面板。**零依赖、无构建、无外部资源** | ✅ 主战场，文案/面板/配色/演示步骤全在这 |
| `app-real/` | 应用「猫&鱼」的**构建产物**（纯静态，数据全虚构存 localStorage） | ❌ 不要手改，它是 `catfish-demo/` 编译出来的 |
| `catfish-demo/` | 应用的**源码副本 + 演示补丁**（可自己构建）。*仅「源码交接包」内含；若你手上没有这个目录，说明拿到的是轻量包，只能改 `index.html`* | ✅ 要改应用本身就在这里改，改完重新构建 |

## 两边怎么同步更新（重要）

没有自动同步机制，靠约定避免分叉：

1. **只改展示壳**（文案、面板、配色、演示步骤）→ 直接改 `index.html`，不需要构建，两边不会冲突。
2. **改应用本体** → 在 `catfish-demo/` 里改，改完跑：
   ```bash
   cd catfish-demo
   npm install        # 首次，包里故意不含 node_modules
   npm run build
   ```
   用 `catfish-demo/dist/` 的内容整体替换 `app-real/`（替换前先删 `dist` 里的旧文件、并重新删掉 `assets/hero-couple.*`，见下方「构建后清理」）。
3. **谁改了应用源码，请把 `catfish-demo/src/` 的改动 diff 同步回另一边**（或直接把整个 `catfish-demo/` 目录发回去）。否则下次从另一侧重新构建会覆盖掉你的修改。
4. 建议把 `vibe-coding/` 整个目录当作**一个整体替换单元**：更新时整目录覆盖，不要只挑文件。

## 构建后清理（每次重新构建都要做）

```bash
# 1) 产物里删掉未被引用的大图（省 1.5MB；vite 会把 public/ 全量复制进 dist）
rm app-real/assets/hero-couple.png app-real/assets/hero-couple.jpg
```

另外：`npm run build` 在 Windows 上偶发“清空旧 dist 失败”，先手动删 `catfish-demo/dist` 再构建即可，不是代码问题。

## 集成方式（推荐：整页嵌入）

1. 把本包整体放进作品集网站的任意子目录，例如 `vibe-coding/`。**`index.html` 与 `app-real/` 必须保持同级，不能拆开**（app-real 内部是相对路径引用，整体搬移安全）。
2. 在作品集的作品列表里加一个入口（卡片/磁贴均可），链接或 iframe 指向 `vibe-coding/index.html`。iframe 示例：
   ```html
   <iframe src="vibe-coding/index.html" style="width:100%;aspect-ratio:16/9;border:0" title="猫&鱼 项目演示"></iframe>
   ```
   也可以整屏路由页或直接跳转（手机上体验更好）。
3. 编辑 `vibe-coding/index.html` 顶部的 `CONFIG` 对象：把 `portfolioUrl` 改成作品集里返回上一级的地址（「返回文件夹」按钮用）。
4. 部署无任何特殊要求：静态托管即可（GitHub Pages / Vercel / nginx）。无需 SPA rewrite 规则（应用用 HashRouter）。

## 硬约束（务必遵守）

- **不能直接以 file:// 打开**——iframe 跨域限制会让手机框里的触摸模拟失效，必须经 http(s) 访问。
- 不要修改 `app-real/` 里的任何文件（构建产物）。要改应用就改 `catfish-demo/` 源码并重新构建。
- `catfish-demo/` 里**没有 `.env`**（这是故意的）：无 Supabase 配置时应用自动降级到 localStorage，不会接触真实数据。**不要给它补 `.env`**。
- 演示构建已把验证码改为 `'demo'`（真实验证码已移除；正常流程也不会到验证页）。源码里不要把它换回去。
- 若要改**应用本体**（页面/交互/视觉）：在 `catfish-demo/src/` 改，参考下面的「演示补丁清单」保持与构建一致。

### 演示补丁清单（`catfish-demo/` 相对原项目的全部差异）

改动都很小且孤立，重新应用或反向合并时按这张表对：

| 文件 | 改动 |
|---|---|
| — | 不拷 `.env`：无 Supabase 配置 → 自动降级 localStorage |
| `public/demo-boot.js`（新增） | 首次进入写虚构种子数据；预置身份与已验证状态；监听 `vibe:reset` 实现重置 |
| `index.html` | 注入 `<script src="./demo-boot.js">`；移除 Google Fonts 外链（会阻塞首屏） |
| `vite.config.js` | 去掉 PWA 插件（SW 会与宿主站点冲突）；`base: './'` |
| `App.jsx` | BrowserRouter → HashRouter（嵌入任意子路径都不会把地址推回根路径） |
| `hooks/useAuth.js`、`pages/Verify.jsx` | 验证码改为 `'demo'`（移除真实码） |
| `pages/Home.jsx`、`pages/food/FoodRecords.jsx` | 加 `data-demo` 标记（引导演示高亮用） |
| `components/common/PageTransition.jsx` | `StaggerItem` 改为透传 props（否则 `data-demo` 传不下去） |
| 各页 `src` 内图片引用 | `/app-real/assets/...` → `./assets/...`（可搬性） |
- 手机视口内的演示数据存在浏览器 localStorage（键前缀 `catfish_`），是全站共享的命名空间，但作品集网站一般不会用这个前缀，无需处理。

## 可选打磨

- 右侧面板文案：`index.html` 里 `<aside class="panel">` 区段
- 引导演示 6 步：`CONFIG.demoSteps`（选择器基于演示构建内的 `data-demo` 标记，别改成别的类名）
- 配色：`index.html` `<style>` 顶部 `:root` 变量（猫橙 `#F6B26B`、鱼蓝 `#A8DADC` 已就位）
- 顶栏面包屑「作品集 / Vibe Coding / 情侣记录」按网站实际导航结构调整

## 验收清单

本地起任意静态服务器（`npx serve .` 或 `python -m http.server`），打开 `vibe-coding/index.html`：

- [ ] 手机框内渲染出「猫&鱼」首页：奶油色调、顶部天数计数、票根卡
- [ ] 鼠标在应用内拖动可以滚动，点击有触点圆圈反馈
- [ ] 点「播放演示」：字幕条出现，票根卡被高亮，逐步推进到美食模块 → 记录列表 → ＋ 新建表单
- [ ] 点「重新开始」：数据复原为 3 条虚构种子记录
- [ ] 浏览器控制台无报错、无任何外部网络请求（字体/CDN 均已移除）
